## 一、表面判定（先定构成，再谈配色）

这是一张 **Operate 表面**（对"待确认条目"采取动作：写入/驳回/改稿/提交生成），
次要属性是 **Command / Inspect**（键盘驱动 + 钻进单条看判据）。

推论：**不出现 hero，不做等权卡片网格**。构成 = 密排线程 + 常驻待确认队列，动作入口与选中态占主导。

> v1 被判"丑"的真正原因不是配色，是构成与装饰：假 SVG 商品插画、图标栏的橙色竖条、渐变光晕、没有排版系统。

## 二、参考对象与取舍（来源 → 采纳 / 不采纳）

| 来源 | 给出什么 | 采纳 | 理由 |
|---|---|---|---|
| **Linear**（本地设计系统库） | 暗色原生、**靠明度分层而不是阴影**、半透明白描边（.06/.10）、单一强调色、字重只到 600、正文用 #f7f8f8 而非纯白 | 全部采纳 | 正是"暗色工具界面不廉价"的底层手法；v1 用大量描边和彩虹标签因此显脏 |
| **Claude Artifacts**（官方 UX 拆解） | 线程内卡片作为"交接点"，右侧分栏放交付物，**预览/源码做相邻页签**，输入框始终留在底部 | 采纳 | 提案卡 = 交付物；中文稿 / EN 生图版做成相邻页签，而不是上下堆两块 |
| **Cursor**（批量 diff 审阅） | 全部改动**一起呈现**，可逐条或一次性接受 | 采纳 | 对应"待确认 N 条 → 写入全部" |
| **GitHub review** | 批量提交条 + 勾选状态 | 采纳 | 队列底部的"写入全部 3 条 ⌘⏎" |
| **审批队列实践**（CopilotKit / Cloudflare / Agent Inbox / The Agent Practice 四家一致） | ① 审批卡必须给出**要做什么 + 依据 + 批准后会怎样** ② 一键批/驳 ③ **驳回必须写理由，理由回流给 AI** ④ 点击即执行（不要"批了再排队执行"） | 采纳① ② ③ | ④ 不适用：这里不是不可逆副作用，生图本身可重试 |
| 同上 | "超时即拒绝 / 签名审计 / 多审批人" | 不采纳 | 单人本机使用，架不起这些机制；先记着，将来分发给团队再谈 |
| **Mobbin 式成品画廊**（卷帘、杂志感产品页） | 大图叙事 | 不采纳 | 那是 Decide/Learn 表面，与本站功能无关 |

## 三、AI 味自检（10 条，分越低越好）

**v1 = 4/10**：假 SVG 商品插画、图标栏橙色竖条、渐变光晕、默认字体无排版系统。

**v2 = 1/10**：只剩 #9（用了系统字体栈）—— 这是**有意选择**：中文界面用系统汉字字体是对的，
但排版系统是明确规定的：字号 11/12/13/13.5/17/22，字重 400/500/600，≥20px 收紧字距，
证据类内容（英文稿、文件路径、键位、规格）一律等宽。

## 四、交互（这一页真正想让人记住的一件小事）

**"记忆注入"从不可见变成可见**：底部 «本轮记忆» 条列出本轮注入了规则多少字、命中了哪两条纠错；
输入框聚焦时它亮起（橙色描边）—— 让"它带着哪些记忆在回答"这件事当场可见。

次要动作：**队列行点开看判据 → 驳回必须写理由（理由回流，之后不再提）**。

## 五、验收标准（改完要能一条条测）

1. 1440×900 单屏不滚动；窄屏降级为上下两段
2. 队列单击 ✓ / ✕ 即结算：行消失、角标递减、写全部按钮文案跟着变
3. 展开行点驳回但不写理由 → **拦住并聚焦输入框**
4. 正文对比度 ≥ 12:1；次要文字 ≥ 8:1（已按 #c9cfd8 / #8a8f98 计）
5. 只有一处强调色；类型区分靠文字，不靠颜色（v2 已去蓝去绿）
6. `prefers-reduced-motion` 下不动画

```
点 ✓ 写入一条：ROWS=2 BADGE=2 ✓
展开行点驳回不写理由：被拦住、flash 提示、焦点落到理由输入框 ✓
```

## 为什么浅色

工作对象是**彩色商品图**：深色底让图片发灰，浅色底里商品图才是主角。另加三条实际理由——
截图当交流方式（浅色截图清楚）、要投屏培训、输出 PDF/手册不翻车。

## 强调色降级（这条决定了"不廉价"）

主色改**近黑**（按钮 / 标题）；品牌橙只留给**「待你决策」与角标**（待确认角标、待采纳那条、命中标签）。
橙色一旦铺满按钮，就会和彩色商品图抢戏。

## 过程中撞到并解决的一个真问题：`frontend/out` 被别的进程锁住

`npm run build` 需要先清空 `frontend/out`，但 Windows 报
`EBUSY: rmdir out/_next/static/css`（中文提示"另一个程序正在使用此文件"）。
试过：杀掉占用 3111 的后端（无效）→ 退出终端 CWD（无效）→ `rd /s /q`（无效）→
Restart Manager API 查占用者（**err 5，被拒**）。占用者不是我的进程，且不该为此杀用户的软件（WorkBuddy/WorkDaddy 在跑）。

**解法**（顺手把这个老毛病一起治了）：
1. `backend/server.js` 的 `STATIC_DIR` 支持 `NOVA_FRONTEND_DIR` 覆盖（原来是写死 `../frontend/out`）
2. 在 `D:\ai\123\nova-fe-build` 建一份构建目录（源码 + `mklink /J` 软链 node_modules，
   `next.config.ts` 里读 `../package.json` 改成本目录），在那里构建出干净的 `out`
3. 启动后端时带上 `NOVA_FRONTEND_DIR=D:/ai/123/nova-fe-build/out`

→ 当前开发部署（3111）服务的就是这个新产物 ✓

**以后两种走法**：① 正常情况仍可直接在 `frontend/` 构建（锁释放后）；
② 再遇到锁，就重复上面第 2、3 步。建议把这个写进 dev 流程。
